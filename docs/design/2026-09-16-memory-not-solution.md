# 非代码面不叫 solution

- 日期：2026-09-16
- 来源：agent 对话
- 状态：已确认
- 问题：代码图之外那一面该叫什么，里面放什么

## 背景

产品文案和 `DESIGN.md` 把非代码面叫 **solution / 解决方案 / 解法树**。这把该面收窄成「排障写过的解法」，和本意不符。

本意：除代码外、所有需要记下的东西放在**同一棵树**上。可能包括用户习惯、项目事实、设计方案、解法等多个方向。

## 决策

- **两面**：**代码图**（从仓库解析）和 **记忆**（代码里没有、需要写下的）。英文 plane 名是 **memory**，一条叫 **a memory**，树叫 **memory tree**。CLI 已是 `cam add` / `cam recall` / `cam mem`，动词不用改。
- **不叫 solution / 解决方案 / 解法。** 解法只是记忆的一种内容，不是存储的名字。也不按习惯 / 事实 / 设计 / 解法拆表或拆命令。
- **不叫 knowledge / 知识库。** 偏项目知识，对「用户习惯」偏弱；也不另起 notes / 笔记当 plane 名（太轻）。评测语料（coding-agent-life）可以仍是解法向的，那是语料，不是产品名。
- **类型写在摘要和正文里**，不作为 schema 字段来分流检索。以后若要过滤，再加可选标签，不先做分类系统。

## 架构

```
cam
├── 代码图   从源码抽出（index / sync / watch / ls / read / ref）
└── 记忆     写进去的（add / recall / mem）
             习惯 · 事实 · 设计 · 解法 · …
```

- 代码图：仓库里已经有的结构。
- 记忆：仓库里没有、但下次还要用的记录。同一套向量 + BM25 + RRF、同一套遗忘 / 更新规则。

内部表名 `solutions`、函数 `add_solution`、评测 `--track solutions` 仍是旧标识，与对外名称脱节；改 schema / 评测旗标是后续迁移，不阻塞对外用词。

## 否决方案

- **继续叫 solution / 解法树**：只覆盖排障写回，装不下习惯和事实。
- **按方向拆成多套存储**：违背「放在一起」；召回和遗忘规则会分裂。
- **用 knowledge 当英文 plane 名**：和 `cam mem`、已有「记忆规则」不一致。

## 相关路径

- `DESIGN.md` — 产品设计；原「解决方案」节改为「记忆」
- `README.md` / `README.zh.md` — 对外两面用词
- `src/main.rs` — CLI about / help
- `src/db.rs` — 表仍为 `solutions`（待迁）
